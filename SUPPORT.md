# Getting help

Margince is an early proof of concept with no release yet. There is **no promise of
support**: a small team answers issues when it can.

Where to go, in the order to use them:

1. **[docs/README.md](docs/README.md)**: the map of the docs. Most answers to a "how do you"
   question are in the docs already.
2. **[docs/reference/make-targets.md](docs/reference/make-targets.md)**: the build and dev
   commands.
3. **[docs/reference/configuration.md](docs/reference/configuration.md)**: the config file,
   its settings and the endpoints for running the product.
4. **[docs/explanation/backend-onboarding.md](docs/explanation/backend-onboarding.md)**:
   a map of the code and the order to read it in.
5. **[CONTRIBUTING.md](CONTRIBUTING.md)**: how a change gets from your
   machine to `main`, and what the gates check.
6. **A GitHub issue**, using one of the issue forms. A bug report that lists the steps
   to show the bug gets an answer sooner than a question. Someone can work on it at once.

Two things must **not** go in a public issue:

- **A security vulnerability.** Report it in private; see
  [SECURITY.md](SECURITY.md).
- **A Code of Conduct report.** Mail `conduct@gradion.com`; see the
  [Code of Conduct](CODE_OF_CONDUCT.md).

Margince has the BUSL-1.1 license, and you may run it in production for free for up to 10
seats. Questions about a license past that limit, or about support you buy, go to
[gradion.com](https://gradion.com) and not to this repository.
