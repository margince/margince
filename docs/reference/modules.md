# Module catalog

The bounded capabilities under `backend/internal/modules/`. Use this to find the module a change
belongs to, or to place a new one. The page is hand-written, so `internal/modules/` is the authority
on which capabilities exist: a directory this catalog has not caught up with is still a module. For the *why* of the module
boundary (the DAG, the two spine shapes), see [explanation/architecture.md](../explanation/architecture.md);
for the store/write mechanics every module shares, see
[explanation/write-backbone.md](../explanation/write-backbone.md).

## Module shape

A module is flat by default: store, contract mapping, transport handlers and provider slice in one
package. It gets a subpackage only for a protocol adapter, an independent engine or a hidden
ruleset. Some modules are seam-shaped (a registry, a factory) instead of an HTTP capability; the
Spine column says so.

The "Owns tables" column is the ownership declared in each module's `doc.go` and enforced by
`backend/gates/tableownership_test.go`, which also ratifies the few sanctioned cross-store writes
(merge relinks, GDPR erasure). The import, ownership and spine rules are in
[architecture.md](../explanation/architecture.md); the gates that enforce them are listed in
[backend-onboarding.md → gates](../explanation/backend-onboarding.md#the-gates-that-judge-your-pr-fitness-functions).

still answer a generated `501` until its handler lands, so the column is not an implementation-status

**Per-reader view state and derived caches**, written without an audit row.
A row generated for one reader is never served to another, so an audit trail

- `user_record_view` (the per-user visit baseline) and `suggestion_dismissal` in `compose/company360`
- `contact_moment_dismissal` in `compose/contact360`
- `company_brief` in `compose/companybrief`
- `company_dossier` and `company_growth_fit` in `compose/companydossier`
- `contact_brief` in `compose/contactbrief`
- `deal_status_card` in `compose/dealstatus`: the deal page's written card, cached per reader on a

- `company_scan` in `compose/companyscan`: the model's reading of one account for one reader, which
  also carries the read in flight and announces every transition on the AI activity rail

Compose-level features (company context, the cold-start transport, reply drafting, deep-read
orchestration, the AI certification lane) are not modules either: they wire module stores together
([explanation/composition-layer.md](../explanation/composition-layer.md)).

## Where cross-module edges are wired

A module never reaches a sibling; the composition root injects the edge (how that works:
[explanation/composition-layer.md](../explanation/composition-layer.md)). The current edges (wired in
`internal/compose/server.go`):

- **deals ← projects**: whether a project may be attached to a deal, and moving a
  won deal's project into delivery, both inside the deal write's own transaction
  (`deals/projectseam.go`, bound in `compose/installseam`).
- **identity's workspace seed** ← deals (default pipeline) + consent (default purposes/retention) +
  automation (starter automations) + activities (booking page), in one bootstrap transaction.
- **agents' staging/redemption** ← approvals (adapter), and **agents' approval queue** ← approvals
  (a second adapter: the tools that list, read and answer what is waiting).
- **automation's action seams** ← collections (add-to-list), activities + consent (draft-email
  compose + the outbound suppression gate), approvals (🟡 staging), activities (the no-activity/
  check-in candidate scan), identity (the match-time owner-permission re-check via `authz.Resolver`).
- **consent's DSR erasure** ← privacy's `Eraser`.
- **signals' relationship strength** ← contacts's store (adapter).
- **activities' outbound gate** ← consent (the suppression gate) + contacts/consent public seams.
- **webhooks' owner-scope fan-out** ← identity (the enqueue-time owner-visibility re-check via `authz.Resolver`).
- **imap connect** ← capture's connector registry (adapter).
- **filtered export** ← collections' saved-view/list source (adapter).

To place a new capability: add `internal/modules/<name>/` (flat), give it a `doc.go` with a "Tables
owned" list, follow one spine shape, and wire any cross-module need as a compose adapter, never a
sibling import.
