# Report a problem

Mail a short description of the problem to **bugs@gradion.com**, with a subject
line that starts `[Margince]`. A picture of the screen helps.

You do not need a GitHub account, and nothing you write is posted as it stands.

### How do I report a problem or request a feature?
To report a problem in Margince, open the account menu, choose **Help and feedback**, then **Report a problem**. It opens the public form for problems, with your release filled in. **Request a feature** opens the form for a feature you miss. Without a GitHub account, mail **bugs@gradion.com** instead.
Also called: send a problem, error report, feature request, contact support, help menu.

### How do I ask for a new feature?
To ask for a new feature in Margince, open the account menu, choose **Help and feedback**, then **Request a feature**. It opens the public form for a feature you miss.
Also called: feature request, suggest a feature, missing feature.

## What to leave out

Do not paste customer data that does not show the problem. A name, an address,
or the text of a mail is data about a real human.

The Margince team sees the problem again on test data, and writes the public
issue from that. Your own data stays out of it.

## A security problem goes somewhere else

Seeing data you should not see is a security problem.

Mail it to **security@gradion.com**, the private address the project's
security policy names. Never send
it to the address above, and never write it into a public issue. A problem mail
can be sent on to somebody else; a security report must not be.
