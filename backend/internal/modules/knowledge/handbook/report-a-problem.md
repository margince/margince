# Report a problem

Mail a short description of the problem to **bugs@gradion.com**, with a subject
line that starts `[Margince]`. A picture of the screen helps.

You do not need a GitHub account, and nothing you write is posted as it stands.

## What to leave out

Do not paste customer data that does not show the problem. A name, an address,
or the text of a mail is data about a real human.

The Margince team sees the problem again on test data, and writes the public
issue from that. Your own data stays out of it.

## A security problem goes somewhere else

Seeing data you should not see is a security problem.

Mail it to the private address in [SECURITY.md](../../SECURITY.md). Never send
it to the address above, and never write it into a public issue. A problem mail
can be sent on to somebody else; a security report must not be.
